## 0. 실DB 검증 결과 (2026-08-31, Supabase 직접 확인) — ⏸️ 조치는 사용자 결정으로 보류

아래는 정적 분석이 아니라 운영 DB(`epgvcudkckrgpsegzbyp`)에서 직접 쿼리로 확인한 사실.
사용자 결정: **PIN 방식은 유지(잘 동작 중), 보안 조치는 현재 보류.** 나중에 재개할 때 참고용.

- **RLS는 10개 테이블 모두 켜져 있음.** 운영자 판별 `is_operator_or_admin()`은 `user_profiles.role IN ('admin','operator')`를 `auth.uid()`로 확인하는 정상 구조. 운영자 계정 = **admin 1명**(auth 연결됨). → 안전한 정책은 이미 존재하고 로그인 세션에서 정상 작동.
- **문제: `teams`/`matches`에 안전 정책과 별개로 `USING (true)` 중복 정책이 덧씌워져 있음.**
  - `teams`: `teams_update(true)`, `teams_delete(true)`, `teams_insert`, 중복 SELECT
  - `matches`: `matches_update(true)`, `matches_delete(true)`, `matches_insert`, 중복 SELECT
  - Postgres는 permissive 정책을 **OR**로 합치므로 느슨한 쪽이 이김 → **anon 키로 팀·경기 수정/삭제 가능** (정적 분석 예상보다 심각: 읽기뿐 아니라 쓰기·삭제까지 열림).
- **`clubs`/`ties`/`tie_rubbers` 쓰기는 `authenticated`로 제한됨(정상).** 단 SELECT는 public → `clubs.captain_pin` 노출.
- **PIN 컬럼 anon SELECT로 읽힘 확정**: `teams.pin_plain`, `clubs.captain_pin`, `venues.pin_plain`.
- **위험 RPC 전부 `anon=true`(외부 실행 가능)**: `rpc_submit_match_result`, `rpc_generate_tournament`(대진표 삭제·재생성), `rpc_generate_groups`, `rpc_calculate_standings`, `rpc_advance_tournament_winner`, `rpc_create_team_groups`, `rpc_generate_team_tournament`, `rpc_fill_tournament_slots` 등. (`rpc_generate_tournament`은 오버로드 2개 존재)
- **마이그레이션 008 미적용 확정**: `rpc_admin_record_score` 인자에 `p_token` 없음 → 무인증.
- **주의(재개 시 순서)**: 선수 셀프 체크인(`pin/page.tsx`의 anon `teams.checked_in` UPDATE)은 **현재 `teams_update(true)` 때문에 동작 중.** `true` 정책 제거 전에 반드시 `rpc_pin_checkin` 같은 RPC로 먼저 교체해야 체크인이 안 깨짐. (정적 분석의 H1 "체크인이 원래 실패한다"는 실제와 다름 — 뚫린 정책 덕에 되고 있었음.)
- `push_subscriptions`는 `deny_all` + `anyone can insert` + service_role select/delete → 읽기 보호됨(정상).

**재개 시 최소 조치 순서**: ① `rpc_pin_checkin` 추가+프론트 교체 → ② `teams`/`matches`의 `true` 중복 정책 제거 → ③ 위험 RPC `REVOKE EXECUTE FROM anon` → ④ 008 적용 → ⑤ (선택) PIN 컬럼 노출 차단. ①~④는 선수 PIN 화면을 안 건드림.

## 1. 🔴 긴급 — 보안 문제 (가장 먼저 처리 권장)

### 1-1. 모든 PIN이 사실상 공개 상태
- `GET /api/push/subscribers?event_id=...` 가 **인증 없이** 전체 팀 PIN(`pin_plain`)과 캡틴 PIN(`captain_pin`)을 평문으로 반환 (`src/app/api/push/subscribers/route.ts:54,64`)
- `teams` 테이블 RLS가 `SELECT USING (true)` (`03_rls.sql:34`) → anon 키만 있으면 PostgREST로 `teams?select=pin_plain` 직접 조회 가능
- `lineup/[tie_id]` 페이지는 양 팀 `captain_pin`을 브라우저로 내려받아 **클라이언트에서 비교** (`lineup/[tie_id]/page.tsx:136-137,173-174`)
- PIN = 점수 제출 권한이므로, PIN 유출 = 아무나 남의 경기 점수 입력 가능

### 1-2. 인증 없는 API 라우트 (service_role 사용)
전부 URL만 알면 호출 가능:
- `api/admin/venues` — POST/PATCH/DELETE 무인증. PATCH는 임의 컬럼 덮어쓰기 가능 (`route.ts:30-34`)
- `api/sync/*` 전체 — `push-results`는 App A(제주테니스 랭킹 DB)에 **랭킹 포인트를 쓰는** 엔드포인트인데 무인증 + `Access-Control-Allow-Origin: *`
- `api/sync/pull-team` — club_members를 **삭제 후 재삽입** → 악용 시 명단 삭제 무기화 가능
- `api/sync/auto-pull` — `CRON_SECRET` 미설정 시 가드가 통째로 스킵됨 (`route.ts:18-22`)
- `api/notify/court` — 아무나 실제 구독자에게 푸시 발송 가능 (스팸)
- `api/push/logs`, `api/push/check` — 무인증 service_role 읽기

### 1-3. 운영자용 RPC가 anon 키로 호출 가능
`REVOKE`/권한 설정이 어디에도 없음 → 모든 `rpc_*`가 anon 실행 가능:
- `rpc_submit_match_result` — 아무나 임의 경기 점수/승자 확정
- `rpc_generate_tournament`, `rpc_generate_groups` 등 — **조편성/대진표 삭제·재생성** 가능
- `rpc_calculate_standings`, `rpc_advance_tournament_winner` — 순위/진출 조작 가능

### 1-4. `rpc_admin_record_score` 토큰 검증 미적용
마이그레이션 008이 **주석 처리된 템플릿 상태**로, 실제 DB에는 무인증 버전이 살아 있음.
호출처 3곳(`lib/team-api.ts:359`, `admin-pin/manage:440`, `lineup/[tie_id]:268`) 모두 `p_token` 없이 호출.
특히 `lineup/[tie_id]`는 양측 라인업 제출 후엔 **PIN 확인 없이** 점수 입력 화면 진입 가능 → URL만 알면 관중도 러버 점수 입력 가능.

### 1-5. 대시보드 인증이 클라이언트 전용
`middleware.ts` 없음. `dashboard/layout.tsx`의 `useEffect` 리다이렉트가 전부 → 실질 방어선은 RLS뿐인데 위 항목들처럼 구멍이 많음.

**권장 조치 (순서대로):**
1. `push/subscribers` 응답에서 PIN 제거 (운영자 화면에는 별도 인증 후 제공)
2. 모든 `/api/*` 라우트에 공통 인증 (Supabase JWT 검증 또는 `x-admin-secret` 헤더), `CRON_SECRET` 필수화(fail-closed)
3. `teams`/`clubs`/`venues`의 PIN 컬럼 anon 노출 차단 (컬럼 제외 뷰로 교체 + `REVOKE SELECT`)
4. 운영자용 RPC 전체에 `REVOKE EXECUTE FROM anon` + 필요한 것만 토큰 검증 추가
5. 마이그레이션 008 실제 적용 (`rpc_admin_record_score` 토큰 필수화)
6. `lineup` 점수 입력에 캡틴 PIN 재확인 추가

## 2. 🟠 대회 중 사고 가능성 있는 버그

### 2-1. 개인전 점수 입력: "내가 항상 승자" + "승자는 무조건 6"
`pin/matches/page.tsx:476-483`
- 제출하는 사람의 팀이 무조건 승자로 기록됨. **패자가 먼저 제출하면 결과가 뒤집혀 저장** (선착순, 정정 절차 없음)
- 점수가 `6:0`~`6:5`만 가능 → 7:5, 7:6(타이브레이크) 기록 불가
- 권장: 승자 선택 UI 추가 + 상대 점수 6 이상 허용(7:5, 7:6), 장기적으로 상대측 확인(양측 컨펌) 절차

### 2-2. 점수 "강제 수정"이 대진표 갱신을 건너뜀
`dashboard/courts/page.tsx:620-639` — RPC 실패 시 matches를 직접 UPDATE → 승자 진출/TBD 채우기 로직이 안 돌아서 **본선 대진표가 조용히 어긋남**. 강제 수정 후에도 진출 처리 RPC를 태우거나, 최소한 경고 표시 필요.

### 2-3. 본선 슬롯 채우기가 "선수 브라우저" 담당
`pin/matches/page.tsx:412-474` — 조별 마지막 점수 제출한 선수의 브라우저가 `rpc_fill_tournament_slots`를 호출. 제출 직후 앱을 닫으면 진출 처리가 누락되고, 동시 제출 시 병렬 호출. 권장: DB 트리거 또는 서버 측(cron/webhook)으로 이동.

### 2-4. 셀프 체크인이 조용히 실패 중 (기능 자체가 동작 안 함)
`pin/page.tsx:121-124` — anon 키로 `teams.checked_in` UPDATE하는데 RLS(`op_update`)가 운영자만 허용 → **0행 매치로 조용히 무시됨**. "PIN 로그인 = 출전 신고" 기능이 실제로는 저장 안 되고 있을 가능성 높음. → RPC(`rpc_pin_checkin`)로 전환 필요. **실DB에서 checked_in 값 확인 권장.**

### 2-5. 단체전 tie 결과 처리 동시성
`rpc_calculate_tie_result`(011)가 tie에 `FOR UPDATE` 잠금 없이 집계 → 두 러버 점수가 동시에 들어오면 **이중 진출 처리** 가능. (개인전 쪽은 잠금 있음 — 단체전만 누락)

### 2-6. 1000행 제한 (Supabase 기본 limit)
`dashboard/courts:267`, `admin-pin/manage:155`, `teams/ties` 등 `.limit()` 없는 전체 조회 → 대형 대회(경기 1000+)에서 **일부 경기가 화면에서 조용히 사라짐**.

### 2-7. KST 시간대 불일치
`layout.tsx:64`, `courts:180`, `admin-pin:25`, `venue:25` 등이 UTC 기준 `toISOString().split('T')[0]` 사용 → **아침 9시 이전에는 '어제'로 계산**되어 대회 자동 선택/날짜 필터가 어긋남. `Asia/Seoul` 기준으로 통일 필요.

### 2-8. 트랜잭션 없는 다중 삭제/수정
- `tournament/page.tsx:152-157` — bracket_nodes → matches 순차 삭제, 에러 무시
- `courts` 자동배정 루프 — 중간 실패 시 반쪽 배정
- `sync/pull-team` — 명단 삭제 후 삽입 사이에 타임아웃 나면 **명단 소실** (10분마다 cron 반복이라 위험 상시 존재)

### 2-9. 동기화 동시 실행 → 중복 팀 생성
10분 cron과 대시보드 수동 동기화가 겹치면 둘 다 "미동기화"로 판단해 중복 insert (`pull-individual`). 잠금/upsert 없음. + Vercel 타임아웃(`maxDuration` 미설정) 시 반쪽 동기화.

### 2-10. 기타
- `teams/ties`: `?event_id=` 없이 진입 시 로딩 스피너 무한 (`page.tsx:51`)
- `useDivisions`: eventId 없거나 에러 시 loading 영구 true (`useDashboard.tsx:19-27`)
- 32강 단체전: `events/[id]` 대진표가 `round_of_32` 미포함 → R32 경기 화면에서 증발 (`page.tsx:777-784`)
- `pin/team`: PIN 충돌 시 `.limit(1)` 무순서 → 엉뚱한 러버에 점수 입력 가능 (`page.tsx:146-152`)
- Enter 연타로 이중 제출 가능 (`pin/matches:741` 등 — submitting 가드 없음)
- `push-results`의 `.or(\`name.eq.${playerName}...\`)` — 이름에 쉼표/괄호 있으면 필터 깨짐/오매칭 (PostgREST 필터 인젝션)
- 조 순위 동률 시 `team_id`(사실상 랜덤)로 진출자 결정 (`06_rpc_tournament.sql:72`) — 세트득실 등 타이브레이크 없음

## 3. 🟡 개선 권장 (중간~낮음)

- `events/[id]/team`: 30초마다 화면 전체가 "로딩중..."으로 깜빡임 (`setLoading(true)`를 갱신마다 호출)
- 다일 대회에서 `match_date` 없는 부서가 목록에서 사라짐 (`events/page.tsx:35-45`)
- 점수 입력 `type=number max=7`은 타이핑을 막지 못함 → 99:0 입력 가능 (JS 클램프 필요)
- 단체전 2-0 스윕인데 3세트 값이 입력돼 있으면 같이 전송됨 (`pin/team:258-259`)
- DB 에러를 "데이터 없음"으로 표시하는 패턴 다수 (`{ data }`만 구조분해, error 무시)
- `auto-pull`이 이벤트 조회 에러를 삼키고 success 반환 (`route.ts:28-36`)
- `sync_log` 무한 증가 (cron마다 클럽당 1행 추가) — 보존 정책/정리 필요
- 인덱스 누락: `matches(court)`, `matches(event_id, team_a_id/team_b_id)`, `push_subscriptions(team_id/endpoint)`, `ties(division_id)` 등
- `pin_sessions`/`admin_pin_sessions`의 event/team FK에 `ON DELETE` 없음 → 이벤트 삭제 막힘
- 로그아웃해도 서버 세션은 12시간 유효 (revoke RPC 없음)
- 시드 데이터: 마스터 PIN `999999`, 팀 PIN `100001~` 순차 — 운영 DB에 있으면 위험
- Math.random() 기반 PIN 생성 — 엔트로피 낮음

## 5. 💡 추천 기능

1. **점수 정정 워크플로** — 참가자 "정정 요청" 버튼 → 운영자 승인 시 반영. 현재는 잘못 입력하면 운영본부 직행뿐
2. **승자 선택 + 실제 스코어 입력** — 2-1의 6:x 제한 해소. 타이브레이크(7:6) 지원
3. **양측 컨펌** — 점수 제출 후 상대팀에 푸시 → 이의 없으면 자동 확정 (오입력·역전 기록 방지)
4. **체크인 현황 실시간판** — 셀프 체크인을 RPC로 고치는 김에, 운영자 화면에 미도착 팀 하이라이트
5. **코트별 QR 코드** — 코트 팻말에 QR → 찍으면 해당 코트 대기열 바로 표시 (현장에서 PIN 입력 부담 감소)
6. **결과 CSV/공유 이미지 자동 생성** — 대회 종료 시 부서별 최종 결과 이미지 (카톡 공유용)
7. **운영자 감사 로그** — 강제 수정/삭제 이력 기록 (지금은 push_logs만 있음)

## 6. 💡 추천 기술

1. **Supabase Realtime 구독** — 현재 15초/30초 폴링 다수 → `postgres_changes` 구독으로 전환하면 즉시 반영 + DB 부하 감소. 점수판/코트 현황에 특히 적합
2. **Sentry (무료 티어)** — 지금은 현장에서 에러가 나면 원인 추적 불가. 클라이언트+서버 에러 자동 수집
3. **middleware.ts** — 대시보드/관리 API 서버측 인증 (클라이언트 리다이렉트 의존 탈피)
4. **zod** — API 라우트 입력 검증 (PostgREST 필터 인젝션 등 예방)
5. **Supabase CLI 마이그레이션 관리** — 지금은 SQL Editor 수동 실행 + 파일 보관 방식이라 "적용됐는지" 추적이 안 됨 (008 사고가 그 예). `supabase db push` 체계로 전환
6. **Vercel `maxDuration` 설정** — sync 라우트 타임아웃 방어
7. **Playwright E2E 스모크 테스트** — "PIN 로그인 → 점수 입력 → 대진 진출" 핵심 경로 자동 검증 (기존 scripts/e2e-team-tournament.mjs 자산 활용)
